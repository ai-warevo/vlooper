# 🧪 План тестирования vLooper: «От нуля до первого Pull Request»

Для того чтобы протестировать **vLooper**, нам нужно создать «лабораторные условия»: имитировать среду GitHub, где бот увидит задачу, возьмется за дело и исправит её.

## Этап 0: Подготовка инструментов (Инвентаризация)
Прежде чем запускать бота, убедись, что на твоем компьютере установлены «кирпичи», из которых строится работа.

1.  **Установи `uv`:** Это менеджер пакетов Python.
    *   *Команда:* [инструкция по инсталляции uv](https://github.com/astral-sh/uv) (обычно `curl -LsSf https://astral.sh/uv/install.sh | sh`).
2.  **Установи `gh` (GitHub CLI):** Чтобы бот мог общаться с GitHub.
    *   *Команда:* В зависимости от ОС (например, `brew install gh` на Mac или скачай установщик для Windows).
3.  **Запусти Ollama:** Это «мозги» бота.
    *   Установи [Ollama](https://ollama.com/), запусти её и скачай модель: `ollama run gemma2` (или другую, которую планируешь использовать).
4.  **Проверь OpenCode:** Убедись, что ты можешь вызвать команду `opencode` в терминале.

---

## Этап 1: Создание «Подопытного проекта» (Target Repo)
Бот не работает в пустоте. Ему нужен проект с ошибкой, которую он должен исправить.

**Шаг 1.1: Создай новый репозиторий на GitHub.**
Назови его, например, `vlooper-test-lab`. Сделай его **публичным** (для простоты теста).

**Шаг 1.2: Подготовь код локально.**
Создай папку `vlooper-test-lab` на компьютере и внутри неё создай два файла:

1.  **Файл с ошибкой (`math_logic.py`):**
    ```python
    def add(a, b):
        # ОШИБКА: функция вместо сложения возвращает разность!
        return a - b 
    ```

2.  **Скрипт проверки (`test.sh`) — ЭТО КРИТИЧЕСКИ ВАЖНО:**
    Бот ориентируется именно на этот файл. Он должен уметь говорить «Да» (0) или «Нет» (1).
    *Создай файл `test.sh`:*
    ```bash
    #!/bin/bash
    # Проверяем, что 2 + 2 = 4
    result=$(python3 -c "from math_logic import add; print(add(2, 2))")

    if [ "$result" -eq 4 ]; then
      echo "Test Passed!"
      exit 0
    else
      echo "Test Failed! Expected 4, got $result"
      exit 1
    fi
    ```
    *Не забудь дать ему права на выполнение:* `chmod +x test.sh`

**Шаг 1.3: Залей это в GitHub.**
```bash
git init
git add .
git commit -m "Initial buggy code"
git remote add origin https://github.com/ТВОЙ_ЛОГИН/vlooper-test-lab.git
git push -u origin main
```

---

## Этап 2: Настройка доступа (Разрешаем боту вход)

Чтобы `vlooper` мог создавать ветки и Pull Request'ы от твоего имени (или от имени бота), ему нужен токен.

1.  **Авторизуйся в GitHub CLI:**
    ```bash
    gh auth login
    ```
    *Следуй инструкциям: выбери GitHub.com, HTTPS, авторизацию через браузер.*
2.  **Получи токен (если используешь отдельного бота) или просто проверь доступ:**
    Для теста проще всего использовать свой текущий токен. Выполни в терминале:
    ```bash
    export GH_TOKEN=$(gh auth token)
    echo $GH_TOKEN # Проверь, что он вывелся
    ```

---

## Этап 3: Запуск vLooper (Включаем «Мозги»)

Теперь переходим в папку самого проекта `vlooper`. **Важно: тебе понадобится два окна терминала.**

1.  **Синхронизируй окружение:**
    ```bash
    cd /path/to/vlooper
    uv sync
    ```

2.  **Первое окно — Запуск Демона (Двигатель):**
    Это основной процесс, который ищет задачи и правит код. Оставь это окно открытым.
    ```bash
    # Запускаем ядро системы
    uv run main.py
    ```

3.  **Второе окно — Запуск TUI (Панель мониторинга):**
    Это визуальный интерфейс, чтобы ты мог красиво наблюдать за процессом.
    ```bash
    # Запускаем интерфейс в другом окне
    uv run main.py --tui
    ```
*Примечание: TUI — это только просмотрщик. Чтобы видеть активность, демон должен быть запущен в отдельном окне.*

---

## Этап 4: Команда к действию (Trigger)

Сейчас бот просто сидит и ждет. Нужно дать ему задачу через GitHub Issue.

1.  Зайди на страницу своего репозитория `vlooper-test-lab` в браузере.
2.  Перейди во вкладку **Issues** -> **New Issue**.
3.  Напиши заголовок и текст:
    *   **Заголовок:** `Fix the addition bug`
    *   **Текст:** `The function add() in math_logic.py is returning a subtraction result instead of addition. Please fix it so that test.sh passes.`
4.  **Нажми "Submit new issue".**

---

## Этап 5: Наблюдение и Проверка (Результат)

Теперь вернись к **второму окну (TUI)**, где запущен `uv run main.py --tui`.

1.  **Что ты должен увидеть в интерфейсе:**
    *   В таблице должна появиться строка с твоим Issue.
    *   Заголовок сверху должен измениться с `💤 IDLE` на `🚀 WORKING ON: #2...`.
    *   Статус задачи должен измениться на `CLAIMED`.

2.  **Финальная проверка:**
    Зайди на страницу своего репозитория `vlooper-test-lab` на GitHub. Если всё прошло успешно, ты увидишь:
    *   Новую ветку.
    *   Открытый **Pull Request** с заголовком вроде "Fix addition bug".

---

## 🚩 Что делать, если не работает (Troubleshooting)

| Симптом | Причина | Решение |
| :--- | :--- | :--- |
| TUI показывает `💤 IDLE` и пустую таблицу | Бот (демон) не запущен или не видит Issue | Убедись, что в **первом окне** работает `uv run main.py`. Проверь, назначен ли Issue на нужного пользователя (`assignee`). |
| Ошибка "Command not found" | Не установлены зависимости | Выполни `uv sync` и проверь пути к `gh` и `ollama`. |
| Бот бесконечно крутится (Loop) | ИИ не может исправить ошибку | Проверь, что в `test.sh` нет синтаксических ошибок и он реально возвращает `exit 1` при неудаче. |
| Тесты проходят, но PR нет | Ошибка прав записи | Проверь, что через `gh` ты можешь вручную сделать push в этот репо. |

# 🧪 vLooper Testing Plan: "From Zero to First Pull Request"

To test **vLooper**, we need to create "laboratory conditions": simulate a GitHub environment where the bot sees a task, takes it up, and fixes it.

## Stage 0: Tool Preparation (Inventory)

Before running the bot, make sure you have the "bricks" installed on your computer that form the foundation of the work.

1.  **Install `uv`:** This is a Python package manager.
    *   *Command:* [uv installation instructions](https://github.com/astral-sh/uv) (usually `curl -LsSf https://astral.sh/uv/install.sh | sh`).
2.  **Install `gh` (GitHub CLI):** So the bot can communicate with GitHub.
    *   *Command:* Depending on your OS (e.g., `brew install gh` on Mac or download the installer for Windows).
3.  **Run Ollama:** This is the "brains" of the bot.
    *   Install [Ollama](https://ollama.com/), run it, and download a model: `ollama run gemma2` (or any other model you plan to use).
4.  **Check OpenCode:** Make sure you can call the `opencode` command in your terminal.

---

## Stage 1: Creating a "Target Project" (Target Repo)

The bot doesn't work in a vacuum. It needs a project with an error that it must fix.

**Step 1.1: Create a new repository on GitHub.**
Name it, for example, `vlooper-test-lab`. Make it **public** (for easy testing).

**Step 1.2: Prepare the code locally.**
Create a folder `vlooper-test-lab` on your computer and create two files inside it:

1.  **File with an error (`math_logic.py`):**
    ```python
    def add(a, b):
        # ERROR: function returns difference instead of sum!
        return a - b 
    ```

2.  **Verification script (`test.sh`) — THIS IS CRITICALLY IMPORTANT:**
    The bot relies specifically on this file. It must be able to say "Yes" (0) or "No" (1).
    *Create the file `test.sh`:*
    ```bash
    #!/bin/bash
    # Check if 2 + 2 = 4
    result=$(python3 -c "from math_logic import add; print(add(2, 2))")

    if [ "$result" -eq 4 ]; then
      echo "Test Passed!"
      exit 0
    else
      echo "Test Failed! Expected 4, got $result"
      exit 1
    fi
    ```
    *Don't forget to give it execution permissions:* `chmod +x test.sh`

**Step 1.3: Push it to GitHub.**
```bash
git init
git add .
git commit -m "Initial buggy code"
git remote add origin https://github.com/YOUR_USERNAME/vlooper-test-lab.git
git push -u origin main
```

---

## Stage 2: Access Configuration (Allowing Bot Entry)

In order for `vlooper` to create branches and Pull Requests on your behalf (or on the bot's behalf), it needs a token.

1.  **Authenticate with GitHub CLI:**
    ```bash
    gh auth login
    ```
    *Follow the instructions: choose GitHub.com, HTTPS, browser-based authentication.*
2.  **Get a token (if using a separate bot) or just check access:**
    For testing, it's easiest to use your current token. Run in terminal:
    ```bash
    export GH_TOKEN=$(gh auth token)
    echo $GH_TOKEN # Verify it is printed
    ```

---

## Stage 3: Running vLooper (Turning on the "Brains")

Now move to the `vlooper` project folder itself. **Note: you will need two terminal windows.**

1.  **Synchronize the environment:**
    ```bash
    cd /path/to/vlooper
    uv sync
    ```

2.  **First window — Running the Daemon (Engine):**
    This is the main process that searches for tasks and fixes code. Keep this window open.
    ```bash
    # Start the system core
    uv run main.py
    ```

3.  **Second window — Running the TUI (Monitoring Panel):**
    This is the visual interface so you can beautifully observe the process.
    ```bash
    # Start the interface in another window
    uv run main.py --tui
    ```
*Note: The TUI is just a viewer. To see activity, the daemon must be running in a separate window.*

---

## Stage 4: Command to Action (Trigger)

Right now, the bot is just sitting and waiting. You need to give it a task via a GitHub Issue.

1.  Go to your repository page `vlooper-test-lab` in your browser.
2.  Go to the **Issues** tab -> **New Issue**.
3.  Write a title and description:
    *   **Title:** `Fix the addition bug`
    *   **Description:** `The function add() in math_logic.py is returning a subtraction result instead of addition. Please fix it so that test.sh passes.`
4.  **Click "Submit new issue".**

---

## Stage 5: Observation and Verification (Result)

Now go back to the **second window (TUI)** where `uv run main.py --tui` is running.

1.  **What you should see in the interface:**
    *   A row with your Issue should appear in the table.
    *   The title at the top should change from `💤 IDLE` to `🚀 WORKING ON: #2...`.
    *   The task status should change to `CLAIMED`.
2.  **Final check:**
    Go to your repository page `vlooper-test-lab` on GitHub. If everything went successfully, you will see:
    *   A new branch.
    *   An open **Pull Request** with a title like "Fix addition bug".

---

## 🚩 Troubleshooting

| Symptom | Cause | Solution |
| :--- | :--- | :--- |
| TUI shows `💤 IDLE` and an empty table | Bot (daemon) is not running or doesn't see the Issue | Ensure `uv run main.py` is working in the **first window**. Check if the Issue is assigned to the correct user (`assignee`). |
| "Command not found" error | Dependencies are not installed | Run `uv sync` and check paths to `gh` and `ollama`. |
| Bot loops infinitely | AI cannot fix the error | Make sure there are no syntax errors in `test.sh` and it actually returns `exit 1` upon failure. |
| Tests pass, but no PR | Write permission error | Check if you can manually push to this repo via `gh`. |
