# 🧪 План тестирования vLooper: «От нуля до первого Pull Request»

Для того чтобы протестировать **vLooper**, нам нужно создать «лабораторные условия»: имитировать среду GitHub, где бот увидит задачу, возьмется за дело и исправит её.

## Этап 0: Подготовка инструментов (Инвентаризация)
Прежде чем запускать бота, убедись, что на твоем компьютере установлены «кирпичи», из которых строится работа.

1.  **Установи `uv`:** Это менеджер пакетов Python.
    *   *Команда:* [инструкция по инсталляции uv](https://github.com/astral-sh/uv) (обычно `curl -LsSf https://astral.sh/uv/install.sh | sh`).
2.  **Установи `gh` (GitHub CLI):** Чтобы бот мог общаться с GitHub.
    *   *Команда:* В зависимости от ОС (например, `brew install gh` на Mac или скачай установщик для Windows).
3.  **Запусти Ollama:** Это «мозги» бота.
    *   Установи [Ollama](https://ollama.com/), запусти её и скачай модель: `ollama run gemma2` (или другую, которую планируешь использовать).
4.  **Проверь OpenCode:** Убедись, что ты можешь вызвать команду `opencode` в терминале.

## Этап 1: Создание «Подопытного проекта» (Target Repo)
Бот не работает в пустоте. Ему нужен проект с ошибкой, которую он должен исправить.

**Шаг 1.1: Создай новый репозиторий на GitHub.**
Назови его, например, `vlooper-test-lab`. Сделай его **публичным** (для простоты теста).

**Шаг 1.2: Подготовь код локально.**
Создай папку `vlooper-test-lab` на компьютере и внутри неё создай два файла:

1.  **Файл с ошибкой (`math_logic.py`):**
    ```python
    def add(a, b):
        # ОШИБКА: функция вместо сложения возвращает разность!
        return a - b 
    ```

2.  **Скрипт проверки (`test.sh`) — ЭТО КРИТИЧЕСКИ ВАЖНО:**
    Бот ориентируется именно на этот файл. Он должен уметь говорить «Да» (0) или «Нет» (1).
    *Создай файл `test.sh`:*
    ```bash
    #!/bin/bash
    # Проверяем, что 2 + 2 = 4
    result=$(python3 -c "from math_logic import add; print(add(2, 2))")

    if [ "$result" -eq 4 ]; then
      echo "Test Passed!"
      exit 0
    else
      echo "Test Failed! Expected 4, got $result"
      exit 1
    fi
    ```
    *Не забудь дать ему права на выполнение:* `chmod +x test.sh`

**Шаг 1.3: Залей это в GitHub.**
```bash
git init
git add .
git commit -m "Initial buggy code"
git remote add origin https://github.com/ТВОЙ_ЛОГИН/vlooper-test-lab.git
git push -u origin main
```

## Этап 2: Настройка доступа (Разрешаем боту вход)

Чтобы `vlooper` мог создавать ветки и Pull Request'ы от твоего имени (или от имени бота), ему нужен токен.

1.  **Авторизуйся в GitHub CLI:**
    ```bash
    gh auth login
    ```
    *Следуй инструкциям: выбери GitHub.com, HTTPS, авторизацию через браузер.*
2.  **Получи токен (если используешь отдельного бота) или просто проверь доступ:**
    Для теста проще всего использовать свой текущий токен. Выполни в терминале:
    ```bash
    export GH_TOKEN=$(gh auth token)
    echo $GH_TOKEN # Проверь, что он вывелся
    ```

## Этап 3: Запуск vLooper (Включаем «Мозги»)

Теперь переходим в папку самого проекта `vlooper`. **Важно: тебе понадобится два окна терминала.**

1.  **Синхронизируй окружение:**
    ```bash
    cd /path/to/vlooper
    uv sync
    ```

2.  **Первое окно — Запуск Демона (Двигатель):**
    Это основной процесс, который ищет задачи и правит код. Оставь это окно открытым.
    ```bash
    # Запускаем ядро системы
    uv run main.py
    ```

3.  **Второе окно — Запуск TUI (Панель мониторинга):**
    Это визуальный интерфейс, чтобы ты мог красиво наблюдать за процессом.
    ```bash
    # Запускаем интерфейс в другом окне
    uv run main.py --tui
    ```

---

## Этап 4: Команда к действию (Trigger)

Сейчас бот просто сидит и ждет. Нужно дать ему задачу через GitHub Issue.

1.  Зайди на страницу своего репозитория `vlooper-test-lab` в браузере.
2.  Перейди во вкладку **Issues** $\rightarrow$ **New Issue**.
3.  Напиши заголовок и текст:
    *   **Заголовок:** `Fix the addition bug`
    *   **Текст:** `The function add() in math_logic.py is returning a subtraction result instead of addition. Please fix it so that test.sh passes.`
4.  **Нажми "Submit new issue".**

---

## Этап 5: Наблюдение и Проверка (Результат)

Теперь вернись к **второму окну (TUI)**, где запущен `uv run main.py --tui`.

1.  **Что ты должен увидеть в интерфейсе:**
    *   В таблице должна появиться строка с твоим Issue.
    *   Заголовок сверху должен измениться с `💤 IDLE` на `🚀 WORKING ON: #2...`.
    *   Статус задачи должен измениться на `CLAIMED`.

2.  **Финальная проверка:**
    Зайди на страницу своего репозитория `vlooper-test-lab` на GitHub. Если всё прошло успешно, ты увидишь:
    *   Новую ветку.
    *   Открытый **Pull Request** с заголовком вроде "Fix addition bug".

## 🚩 Что делать, если не работает (Troubleshooting)

| Симптом | Причина | Решение |
| :--- | :--- | :--- |
| TUI показывает `💤 IDLE` и пустую таблицу | Бот (демон) не запущен или не видит Issue | Убедись, что в **первом окне** работает `uv run main.py`. Проверь, назначен ли Issue на нужного пользователя (`assignee`). |
| Ошибка "Command not found" | Не установлены зависимости | Выполни `uv sync` и проверь пути к `gh` и `ollama`. |
| Бот бесконечно крутится (Loop) | ИИ не может исправить ошибку | Проверь, что в `test.sh` нет синтаксических ошибок и он реально возвращает `exit 1` при неудаче. |
| Тесты проходят, но PR нет | Ошибка прав записи | Проверь, что через `gh` ты можешь вручную сделать push в этот репо. |
