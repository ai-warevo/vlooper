# 🔄 vLooper

<div align="center">

**🇷🇺 Русский • [🇬🇧 English](../en/README.md)**

</div> 

---

**vLooper** — это легковесный локальный демон автоматизации (Loop & Harness Engineering), который превращает стек **Ollama + OpenCode** в автономного ИИ-разработчика для GitHub-организаций.

Он сканирует задачи/PR во всей организации, клонирует репозитории локально и запускает непрерывный цикл «Запись -> Тест -> Исправление» с использованием `OpenCode`, пока задача не будет решена и не будет создан Pull Request.

---

## 🎯 Как это работает (AI Git-Flow)

1.  **Триггер:** Создайте Issue или PR в вашей организации и назначьте его боту.
2.  **Сканирование:** Демон идентифицирует новые задачи через GitHub CLI (`gh`).
3.  **Изоляция:** Воркер клонирует репозиторий в локальное рабочее пространство и создает выделенную ветку.
4.  **Цикл (Harness):** 
    *   `OpenCode` генерирует изменения в коде.
    *   Воркер запускает ваш `./test.sh`.
    *   Если тесты провалены, логи ошибок передаются агенту для автоматического исправления.
5.  **Результат:** Как только тесты пройдены, бот фиксирует (commit) и отправляет (push) ветку, создавая автоматический **Pull Request**.

## 🛠 Требования

*   **Python 3.10+** (управляется через `uv`)
*   **Ollama** (с запущенной моделью, например, `gemma`)
*   **OpenCode CLI**
*   **GitHub CLI (`gh`)** с соответствующими правами доступа

## 🚀 Быстрый старт

### 1. Установка и настройка
Клонируйте репозиторий и настройте окружение с помощью `uv`:

```sh
# Установите зависимости и проект
uv sync

# Настройте ваш GitHub Token (обязательно)
export GH_TOKEN=your_bot_token_here
```

### 2. Запуск демона
Чтобы запустить основное ядро, которое сканирует и обрабатывает задачи:

```sh
uv run vlooper
```

*Альтернативно, запуск из исходников:* `python -m vlooper`

---

### 🛠 Специальные команды

**Повтор неудачных задач (Retry Failed Tasks)**  
Вместо сканирования GitHub на наличие новых задач, эта команда нацелена именно на задачи, помеченные как проваленные в локальной базе данных. Полезно после того, как вы исправили баг, который вызывал предыдущие сбои!

```sh
uv run vlooper-retry
```

**Мониторинг (TUI Dashboard)**  
Чтобы видеть, что делает агент в реальном времени через красивый терминальный интерфейс, **откройте второе окно терминала** и выполните:

```sh
uv run vlooper-tui
```
*Примечание: TUI — это только средство просмотра. Вы должны запустить демон в отдельном окне, чтобы видеть активность.*

## 🛠 Команды для разработки

Используйте эти команды для поддержания качества кода и запуска тестов во время разработки:

| Команда | Описание |
| :--- | :--- |
| `uv run check` | Запуск линтеров и форматировщиков |
| `uv run analyze` | Поиск неиспользуемых файлов и определений |
| `uv run pytest` | Выполнение набора тестов |
| `uv sync` | Синхронизация локального окружения с `pyproject.toml` |

## ⚠️ Важные примечания

*   **Harness (команда тестирования):** Чтобы цикл работал, в корне каждого репозитория должен быть файл `./test.sh`. Этот скрипт должен возвращать `exit 0` при успехе и `exit 1` при ошибке.
*   **Обратная связь:** Если вы оставляете комментарии к Pull Request, бот подхватит их при следующем сканировании и попытается применить запрошенные вами изменения!
